## 1. Does this change the queries?

Yes, but not many. Of the 39 saved filters, **7 change**: 3 because a field has another name, 1 because a label replaces a missing field, and 3 because the PI values are written differently. The other 32 are the same.

| Filter | Before | Now | Why |
| --- | --- | --- | --- |
| MOCK PI planned Initiatives | `"Target PI" = "PI 2026.4"` | `"Target PI" = "PI 5"` | PI value |
| MOCK PI planned Epics | `"Target PI" = "PI 2026.4"` | `"Target PI" = "PI 5"` | PI value |
| MOCK: spillover | `"Target PI" in ("PI 2026.3")` | `"Target PI" in ("PI 4")` | PI value |
| MOCK: Management Attention and Red | `"Management Attention" is not EMPTY OR "RAG Status" = Red` | `labels = mgmt-attention OR "RAG Status" = Red` | No such field; a label is used |

| MOCK: Ready, no Target PI | `ORDER BY "Weighted Shortest Job First Score" DESC` | `ORDER BY WSJF DESC` | Field renamed |

Because Target PI is a dropdown, the value in the query must be spelled exactly as the dropdown option, for example `"PI 5"`.

## 2. The mapping

| In the white paper | On today's Jira | What changes in the mock-up |
| --- | --- | --- |
| Target PI, Actual PI, values like "PI 2027.1" | The same fields, as dropdowns, with values "PI 4", "PI 5" | Current PI is `PI 5`, previous is `PI 4` |
| Enabler Type (a list of kinds) | **Enabler**, radio buttons | One Initiative has Enabler = Yes. Work can be split only into enabler and not enabler, so the investment mix has two groups, not four. |
| The four scores, and Weighted Shortest Job First Score | **WSJF**, one field | The score is typed in as one number. Jira no longer works it out from four parts, so agree the scoring outside Jira and enter the result. |
| Management Attention | No field. The **label `mgmt-attention`** | One Initiative (I3) carries the label. See section 3. |
| Regulatory or Control Change Type | **Is it Regulatory**, Yes or No | One Initiative (I1) has Yes. The kind of regulatory change is not recorded, only whether it is one. |
| Path to Green | **RAG Description** | Same use: the recovery plan for an Amber or Red ticket |
| Date to Green | Not mentioned | Put the recovery date in the RAG Description text |
| Probability | **Risk Probability** | Same values |
| Impact | **Priority** | Uses Jira's own Priority field. Its values may be Highest, High, Medium, Low, Lowest; the mock uses High, Medium, Low. |
| Baseline End Date | **Baseline End** | Same use: on a dependency, the date the supplier promised |

## 3. How "needs management attention" is marked

Decided on 28 November 2026: with a **label, `mgmt-attention`**, not with the "Is it Regulatory" field. That field keeps its plain meaning, so nobody reading it, audit included, is misled.

| Question | Answered by |
| --- | --- |
| Is this work regulatory? | The field **Is it Regulatory** = Yes |
| Does this need a decision from management now? | The label **`mgmt-attention`** |

How the label is used:

- The product lead adds `mgmt-attention` to an Initiative or Capability when a decision is needed that the team cannot make. It goes with RAG Red, and RAG Description says what is needed and from whom.
- The label is removed when the decision has been made. A label left on after that makes the list useless.
- It joins the short list of agreed labels (`pi-committed`, `pi-stretch`, `unplanned`, `pi-descoped`, the `ms-` labels, `milestone`). Nobody invents others.

In the mock-up: I3 carries the label and I1 has Is it Regulatory = Yes. So "Management Attention and Red" returns C2 and I3, and "regulatory Initiatives" returns I1 only.

## 4. What you lose with these fields, and what to do

| Lost | Effect | Workaround |
| --- | --- | --- |
| The kind of enabler | Investment mix shows only enabler against not enabler | Enough to start; use a label if a finer split is wanted |
| The four scores | Jira cannot show why a score is what it is | Keep the four numbers in the Initiative's description, or on the scoring page in Confluence |
| A separate date for recovery | "Date to Green" cannot be sorted or filtered | Write the date at the start of RAG Description: "By 15 Jan: ..." |
| A dedicated Impact field | Priority also drives other things in Jira, such as ordering | Acceptable for Delivery RAID tickets, which are not worked from a backlog |
